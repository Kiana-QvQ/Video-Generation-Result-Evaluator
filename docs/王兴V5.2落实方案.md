## 1. 背景：为什么需要 V5.2（在 V5.1 之上）

### 1.1 V5.1 已证实

- 冻 V3 + `s_realness` 映射 **能保** 真伪与词典序。
- 校准器 / gate / Stage 0 产物检查 **可复现**。
- 二分类上 `s_realness` 真 ≫ AI，质量轴方向正确。
- 仅 2 组 ppt 时，四档类均值挤在 ~0.5，**细序不够**。

### 1.2 产品缺口（V5.2 必须关掉）

```text
缺口 A：领导要看的「真人 > LoRA > Seedance > 多图」仍无稳定离线证明
缺口 B：V5.1 isotonic 用 4 点弱校准，学不到 AI 带内细差
缺口 C：RankHead 门禁仍按 complete_query≥30 一刀切，与「先线性、后扩容」冲突
缺口 D：新 LTX 仅有 LoRA/多图时，如何与真人/Seedance 合法组包未写死
```

### 1.3 论文与演进结论（必须遵守）

见 `docs/论文与技术研究记录.md`、`docs/王兴真伪检测算法演进与当前进展.md`：

| 结论 | 工程含义 |
|---|---|
| 训练集主是真人+Seedance | 二分类学不出四档 |
| RankNet / RankSVM | 小样本成对序主路径 |
| FAME / CapST | LoRA/Seedance/多图是不同 generator；归因是 V5.2+ 可选，不是 Phase1 必须深训 |
| 表情 compatibility ≠ 真实性 | Rank 特征继续禁止 compatibility 主权重 |
| 排序不得改 V3 决策 | cascade 词典序硬约束 |

### 1.4 常理与工程边界

**常理（采纳）：**

```text
同设定下生成越好 → 越接近实拍 → s_rank / s_realness 应更高
当前人工先验 ORDER 可作为排序监督
```

**工程边界（写死）：**

```text
6 组左右只够线性 Rank + 严格 Group 划分，不够深度归因网
缺类组只能计可用 pairwise，不得假装完整四元 ORDER
跨组乱拼真人/Seedance = 学域捷径，禁止
```

## 2. V5.2 目标拆分（四层，禁止混成一个 logit）

| 层 | 目标 | 输出 | 谁负责 | 现状态 |
|---|---|---|---|---|
| **L1 决策** | AI vs 实拍 | `y_decision = y_v3` | 冻结 V3 | ✅ V5.0 |
| **L2 质量** | 多像实拍 | `s_realness ∈ [0,1]` | Realness calibrator | ✅ V5.1 |
| **L3 展示带** | 词典序一个分 | `score_display` | cascade 映射 | ✅ V5.1 |
| **L4 细档** | 当前先验相对序 | `s_rank` / `band_hint` | RankHead | ⚠️ **V5.2 新建** |

```text
禁止：用 L2/L3/L4 改写 L1
禁止：用 L4 破坏 L3 词典序（AI 分永远 < 0.75）
禁止：把四档枚举写成唯一未来接口
允许：L4 在 AI 带内重排 / 标注 band_hint
允许：完整组不够时，用部分序对训练，但报告分开统计
```

学术对应：

| 层 | 方向 |
|---|---|
| L1 | Detection（V3） |
| L2 | One-class / 自然一致性代理（NACO 思想；现 forensics+Drive） |
| L3 | 工程词典序 |
| L4 | Learning-to-rank（RankNet/RankSVM）+ 可选 Attribution（FAME 思想轻量版） |

## 3. 总体架构

### 3.1 四层结构

```text
┌──────────────────────────────────────────────────────────────┐
│ L1 决策（冻结）                                                │
│   V3 → y_v3 ∈ {real, generated}                              │
│   y_decision := y_v3                                         │
├──────────────────────────────────────────────────────────────┤
│ L2 质量轴（继承 V5.1）                                         │
│   z_raw → calibrator → s_realness                            │
│   特征：p_drive_eff, s_direction, p_v3_real                  │
│   禁止：compatibility / identity 抬分                          │
├──────────────────────────────────────────────────────────────┤
│ L3 展示映射（词典序，继承）                                     │
│   real → [0.75,1] = 0.75 + 0.25 * q                          │
│   AI   → [0,0.74] = 0.74 * q                                 │
│   默认 q = s_realness；可选 AI 带内 q 融合 s_rank（§6）         │
├──────────────────────────────────────────────────────────────┤
│ L4 RankHead（V5.2 核心）                                      │
│   组内 pairwise → s_rank ∈ [0,1]                             │
│   band_hint ∈ {real,lora,seedance,multiref} | null           │
│   usable_for_runtime 仅当 ordering 门禁通过                    │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 与 V5.1 cascade 的关系

| 项目 | V5.1 | V5.2 |
|---|---|---|
| 决策 | `y_v3` | 同左 |
| 质量主分 | `s_realness` | 同左（可在 train 组上 **重校准**，不得用 holdout 拟合） |
| RankHead | 禁用 | 线性启用；门禁后 `usable_for_runtime` |
| `band_hint` | 恒 null / 关 | ordering 通过后可写 |
| AI 带内细排 | 仅靠 s_realness | **主路径**用 `s_rank`（方案 A）或消融用重估 w（方案 B） |
| Rank 关 / 失败 | — | **回退 ≡ V5.1** |

### 3.3 词典序与细档不变量（单测必须）

```text
I1: y_decision == y_v3
I2: min(score | y_v3=real) > max(score | y_v3=AI)
I3: 同带内 q ↑ ⇒ score_display ↑
I4: Rank 特征 / 权重不含 compatibility 主项
I5: Rank 关或 calibrator 缺失时 ≡ V5.1
I6: usable_for_runtime=true ⇒ class_ordering_satisfied 且 pairwise≥门槛
I7: 训练/报告不得读取 25+25、32+32 作 fit 列表
```

## 4. 算法与论文落地映射（V5.2 增量）

### 4.1 L4 RankHead

| 论文/技术 | 作用 | V5.2 落地 |
|---|---|---|
| RankNet（Burges） | pairwise logistic | **Phase1 主损失** |
| RankSVM（Joachims） | hinge 小样本备选 | Phase1 消融 A6 |
| FAME | 生成器时空归因 | Phase2 可选：仅 AI 三分类轻量头，禁深骨干 |
| CapST | 胶囊+时序归因 | 仅理念；不进 Phase1 |
| Isotonic（V5.1） | 连续像真度校准 | 保留；可用 train 组重拟合 |

### 4.2 明确不采纳为 V5.2 Phase1 主路径

| 做法 | 原因 |
|---|---|
| 6 组深训四分类 / FAME 全模型 | 必过拟合 |
| 用 compatibility 救细序 | 已实证 AI 可高于实拍 |
| 跨组乱配真人/Seedance 当同 query | 学捷径 |
| Rank 分数翻 V3 | 打穿生产召回 |
| 把 holdout 并入训练再宣称通过 | 不可复现 |
| 固定 70/20/10 当四档保证 | 无监督、无验收 |

### 4.3 推荐消融矩阵

| ID | 设定 | 目的 |
|---|---|---|
| A0 | V5.1 only（s_realness） | 基线 |
| A1 | A0 + train 组重校准 isotonic | 扩校准是否够 |
| A2 | 线性 RankNet → s_rank；展示仍用 s_realness；band_hint 可选 | 保守对照 |
| A3 | AI 带内 rank_in_ai_band（或 blend α=0.35）拉开分差 | **今晚默认（门禁通过后）** |
| A4 | RankSVM hinge 替代 logistic | 损失对照 |
| A5 | A2 + 禁止 seedance_domain 单特征 | 域偏置消融 |
| A6 | A2 + AI 三分类 CE（λ=0.3） | 轻量归因 |
| A7（负对照） | Rank 特征加入 compatibility | 应变差 |

每格报告：holdout pairwise / class_ordering、25+25 flip、词典序、LOGO 均值。

```text
outputs/forensics/wangxing_v5_1_results_summary.json
```

### 5.2 组包硬规则（比「凑 5+1」更重要）

```text
同 group_id 内尽量满足：
  同一身份（王兴）、同一 Prompt、同一表情脚本
  相近机位 / 背景 / 光照 / 时长
角色标签：
  real | lora | seedance | multiref
命名可解析：真人/real、lora/iclora、seedance、多图/multiref
```

**完整组**：四类齐全 → 可计 6 对 pairwise + class_mean ORDER。
**缺类组**：只训/只评 **组内存在的** 序对（典型：`lora ≻ multiref`）；不得报完整 ORDER。

### 5.3 真人 / Seedance 怎么「组合」进 LTX 组

```text
允许（V5.2 开发补齐，默认开启 --complete-from-pools）：
  从 data/MD_CL、data/video 抽真人；从 data/WangXing_Seedance 抽 Seedance
  确定性哈希分配，不复用；排除 25+25 / 32+32 源文件 basename
  写入 completion_mode=pool_fill_dev；same_prompt_matched=false
  holdout（ppt_test2）永不补齐，保持原生同设定四元组

允许（更强）：
  为某 LTX group 挂载「同 Prompt / 同脚本」的 real、seedance 路径
  在 manifest 写 clear matching_key（prompt_id / script_id）

禁止：
  用 25+25 / 32+32 里的样本补齐排序组
  把补齐样本再写回二分类训练集标签
  改 holdout 的原生四元组
```

当前仓库默认：LTX 仅有 LoRA+多图时，用 pool_fill_dev 把 **train 完整组补到 ≥5**（ppt_test1 + 4×LTX），以满足线性 Rank 门禁；对外口径仍须标明「开发代理补齐，非同 Prompt 金标」。

若暂时关闭补齐（`--no-complete-from-pools`）：该组以部分对贡献 `lora≻multiref`；完整 ORDER 仅依赖 ppt 完整组。

### 5.4 划分协议（默认）

```text

交叉验证：GroupKFold / Leave-One-Group-Out
禁止：视频级随机 shuffle（泄漏同 query）
```

### 5.6 序对构造

对每个 group，对所有存在的标签对 `(i,j)` 且 `RANK[i] > RANK[j]`：

```text
构造正样本：score(i) 应 > score(j)
训练时对称：可加入翻转对与标签 0（与现有 weighted_policy 一致）
缺类：跳过；记 missing_pairs
完整四元组理论最大 6 对 / 组
5 完整组 ≈ 30 对 → 仍远小于 200，必须强 L2 / 禁 MLP
```

标签约定（与代码一致）：

```text
ORDER = ("real", "lora", "seedance", "multiref")
RANK  = {real:3, lora:2, seedance:1, multiref:0}
```

注意：`s_realness` 目标方向是「越高越像实拍」→ 映射用 `(3-RANK)/3`；RankHead 内部可用原 RANK 差，但报告分数必须 **越高越好**。

### 5.7 数据门禁（替换「一刀切 30」）

```text
旧：complete_query_count < 30 → 永远 disabled
新（V5.2）：
  min_complete_groups_for_linear_rank = 4   # 可配置；含 ppt+LTX
  min_pairwise_pairs_for_fit = 12          # 例如 2 完整组或等价部分对
  min_complete_groups_for_runtime = 1      # holdout 至少 1 完整组才谈 usable
  深度网仍要求 complete_query_count ≥ 30 且 pairs≥500（本阶段不开启）
```

`rank_head_v5.py` 必须区分：

```text
disabled_insufficient_data
fit_ok_but_ordering_failed
usable_for_runtime=true
```

## 6. L4：RankHead 规格

### 6.1 定义

```text
s_rank = P_proxy(相对「当前 ORDER 先验」位置 | 特征, group 上下文可缺省)
语义：越高越靠「真人」侧；AI 内部用于细排
不是：改写 y_v3
不是：替代 s_realness 的长期「像实拍」定义
```

### 6.2 输入特征（Phase1）

**推荐进入 Rank 向量：**

| 符号 | 来源 | 说明 |
|---|---|---|
| `p_drive_eff` | DriveHead | 真驱动 vs 生成驱动 |
| `s_direction` | forensics direction | 取证方向 |
| `s_realness` / `z_raw` | V5.1 | 已校准像真度（推理用已 fit 的 calibrator） |
| `p_v3_real` | V3 | 只读特征；权重宜受限 |
| `temporal_naturalness_0_1` 等 | forensics components | 可选增强 |

**权重 / 审计：**

```text
p_v3 在 Rank 内建议 cap（如 ≤0.25 归一化后），防复制决策比特
禁止：compatibility_0_1、identity 抬分、FER 置信度主权重
标准化：train 组 mean/std；推理用同一 scaler 写入 JSON
```

### 6.3 模型与损失

**Phase1 主模型：**

```text
sklearn LogisticRegression(
  C=0.5,          # 可网格 {0.1,0.5,1.0}
  class_weight="balanced",
  max_iter=2000
)
或 LinearSVC / RankSVM hinge(margin=0.1~0.5)
禁止：hidden_layer_sizes 非空 的 MLP（pairs<200）
```

**RankNet 风格（与现有脚本对齐）：**

```text
对 RANK(i)>RANK(j)：
  Δ = x_i - x_j
  L = -[ y log σ(w·Δ+b) + (1-y) log(1-σ(w·Δ+b)) ]
对称增强：加入 -Δ 与 y 翻转
```

**可选 Phase2 归因项（仅 AI 子集）：**

```text
L_attr = CE(y ∈ {lora, seedance, multiref})
L_total = L_pair + λ_attr * L_attr     # λ_attr 初值 0.3
禁止 L_total 回传更新 V3 / Drive 主权重（旁路独立 JSON）
```

```text
function cascade_score_v52(y_v3, s_realness, s_rank, policy):
    if y_v3 == real:
        score = 0.75 + 0.25 * s_realness
        return score, "real", "realness_axis"
    if not policy.usable_for_runtime or policy.display_blend.mode == "realness_only":
        score = 0.74 * s_realness
        hint = maybe_band_hint(...) if usable else null
        return score, hint, "realness_axis"
    hint = maybe_band_hint(y_v3, s_rank, policy)
    if policy.display_blend.mode == "rank_in_ai_band":
        score = map_DEFAULT_BANDS(hint, s_rank)   # AI < 0.75，四档可见分差
        reason = "rank_in_ai_band"
    else:  # blend
        q = α * s_realness + (1-α) * s_rank
        score = 0.74 * q
        reason = "rank_blend"
    return score, hint, reason
```

```text
失败：任一步缺失 → 降级到上一可用层（V5.1 / V5.0），不得抛成「假四档」
```

## 21. 技术附录 B：部分对与完整组指标定义

```text
pairwise_ordering_rate：
  分母 = 所有应比较且两端样本都存在的对
  分子 = score(高档) > score(低档) 的对
class_ordering_satisfied：
  仅当该评价子集中四类均有 ≥1 样本时计算
  要求 mean(real)>mean(lora)>mean(seedance)>mean(multiref)
ordering_satisfied（usable 条件）：
  class_ordering_satisfied
  AND pairwise ≥ min_pairwise_threshold
缺类集合：
  只报 pairwise_*；class_ordering=null；不得宣称完整 ORDER
```
